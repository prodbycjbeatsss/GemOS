R01Needs approvalMedium

Group 1 can cut off the third project date

Confirmed in the existing preview

When the web font cannot load, the third project date extends below the recessed panel at mobile widths and at the desktop breakpoint. You can lose useful scheduling information.

Recommended next step

Approve a focused spacing or row-budget adjustment, then check both the intended font and the fallback font. No card code has been changed.

Evidence and expected behaviour

Observed / reproduction

Open the ready state with three projects, block remote fonts, and inspect widths 320, 390 and 840 CSS pixels. At 390 the date bottom is 710.47px while the panel ends at 708.5px; at 840 it extends about 13px below the panel. The normal 1280px desktop test fits.

Expected

Keep all three project dates visible inside the accepted fixed card geometry.

Source: docs/dashboard/group-1/preview.html#L240

R02Needs approvalMedium

Group 1 loses content when text is enlarged

Confirmed in a controlled browser probe

The fixed panels hide content when text becomes much larger. This matters for someone who needs larger text to read the dashboard.

Recommended next step

Approve an enlarged-text layout strategy before changing code. Validate it on Android as well as in the browser.

Evidence and expected behaviour

Observed / reproduction

At 390 CSS pixels, capture each computed font size and double it once. The project and readiness panel content clips; parts of the checklist disappear. This is a controlled font-size probe, not a native Android font-scaling or browser-zoom test.

Expected

Enlarged text must remain available; the design system allows an accessibility reflow exception to the normal fixed-size rule.

Source: docs/dashboard/group-1/preview.html#L241
