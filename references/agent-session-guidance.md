# Agent session continuity and efficiency

## Context continuity

When the runtime explicitly reports compaction, a usage limit, or missing earlier context that prevents a dependable decision, briefly tell CJ what is known. Checkpoint the objective, confirmed decisions, approvals, changes, validation and next action in the current handoff, commit it, and offer a fresh chat once the checkpoint is available. Reload the relevant repository sources before resuming.

Most chat environments do not expose a reliable impending-compaction signal or remaining-context counter. State this limitation when relevant. Do not invent percentages, predict compression from conversation length, or claim an automatic warning can always be delivered before compaction. Never confuse your own concise summary with runtime compaction. Continue authorised work from saved context rather than restarting or treating compaction as cancellation.

## Token efficiency without reduced quality

Start with the repository index and current handoff; inspect the tree and read the relevant documents/source ranges rather than dumping the whole repository or original all-card HTML. Use rg, targeted output and batched independent reads. Reuse fresh evidence; reread when changed or insufficient. Keep progress updates and replies concise, but preserve the reasoning, uncertainties and evidence CJ needs for a decision. Ask one unsettled question at a time and retain already confirmed answers.

Maintain a short current plan and handoff, with links to detailed specifications, research and historical evidence. Consolidate superseded current wording rather than accumulating contradictory instructions. Verify the changes with appropriate checks and record their limits; token saving is not permission to skip required reading, useful research, testing, documentation or GitHub saves.
